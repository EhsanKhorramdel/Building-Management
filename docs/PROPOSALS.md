# Proposals outside the current plan

These are separate from the fixes in [Findings](FINDINGS.md). The timing column marks candidates for an owner-approved round before Phase 10 or for later work. Integrations keep their default-off behavior and provider-neutral configuration.

| Group | Proposal | User value | Effort | Risk | Dependencies | Timing |
| --- | --- | --- | --- | --- | --- | --- |
| Frontend/UX | Preserve the last selected building tab and the unit list view per complex. | Returning residents resume the task they were doing. | S | A remembered tab can be unavailable after a role change. | Existing panel navigation and a per-complex preference key with a fallback. | Later |
| Frontend/UX | Add date and unit filters to the payment report and print the active filter. | Managers can find a period quickly and print only the rows they intend to share. | M | Filtered reports could be mistaken for complete reports. | Report filter request, explicit active-filter label and print checks. | Later |
| Backend | Create a small typed boundary for durations, decimal amounts and optional numbers accepted from forms. | HTML and API clients get the same results for the same values. | M | Conversion could change how empty and zero values are interpreted. | Inventory of affected inputs and form-encoded tests. | Pre-Phase-10 |
| Backend | Add an internal reconciliation view for verified payment conflicts and expired attempts. | A manager can identify what happened from a reference without asking the payer to repeat a charge. | M | Displaying too much could expose payment details. | Role policy, redacted attempt metadata and a documented review process. | Later |
| Database | Introduce database-level paired-coordinate and range checks on both location tables. | Data imports cannot create points that the app cannot display. | M | Historical data may need cleanup before constraints apply. | Data scan, portable SQLite and MySQL migrations, rollback check. | Later |
| Database | Add an append-only transaction state history alongside the current attempt row. | Support can trace when and why an attempt moved between states. | M | Extra rows and retention obligations. | State transition writer, retention policy and scoped access. | Later |
| Security | Add optional expiry and one-use limits to newly generated join links. | Managers can invite one resident without leaving an indefinitely reusable link. | M | A valid invitation can expire before the resident uses it. | Invite model, clock tests and a clear renewal path. | Later |
| Security | Record scoped audit events for role changes, approval decisions and join-link rotation. | Building administrators can explain who changed membership and when. | M | Logs could retain personal data or invitation material. | Event schema, read policy and redaction rules. | Pre-Phase-10 |
| Performance | Load map, chart and realtime bundles only when the relevant panel needs them. | The first building screen downloads less JavaScript on phones. | M | A panel can open before its module or styles are available. | Existing module boundaries, loading states and repeated cold-page measurements. | Pre-Phase-10 |
| Performance | Add cursor pagination to the payer's online payment history. | The Payments tab stays quick as a building accumulates transactions. | M | Users may miss older rows or expect them in the printed report. | Stable order, scoped endpoint, index review and pagination controls. | Later |
| New features | Add a searchable announcement archive with filters for date and active state. | Residents can find an older notice without scrolling through every announcement. | M | Search results must remain scoped to the building. | Existing announcement model, authorization and search tests. | Later |
| New features | Add a building calendar for poll deadlines and charge periods. | Residents can see what is due soon from one place. | L | Jalali date conversion and local time boundaries can cause errors. | Calendar interaction design, date rules and scoped read endpoints. | Later |
| Testing/Tooling | Add form-encoding parity cases for optional numeric fields and blank values. | The suite catches browser-only failures before release. | S | Fixtures could cover only one encoding or locale. | Representative HTML form requests and matching typed payloads. | Pre-Phase-10 |
| Testing/Tooling | Add query-count budgets for the two dashboards and the report across small and large fixtures. | A future change cannot quietly reintroduce queries that grow with unit count. | M | Exact counts can become brittle after framework updates. | Reusable fixtures and growth-based assertions that tolerate fixed setup queries. | Pre-Phase-10 |

There are two proposals in each of the seven groups. Five are candidates for the pre-Phase-10 round.
