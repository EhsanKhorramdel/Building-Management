# Phase 11 feature and interaction audit

Reviewed against `1c4c5e7` on the attachment-private, live-chat baseline. This audit records current behavior and options for owner review. No feature, policy, or implementation choice is approved here.

**Status** describes what exists today. Present means the named interaction works. Partial means there is an existing path, but part of the requested surface is absent or limited. Missing means there is no user-facing capability in scope. **Size** estimates the proposed change, including tests. S is localized, M spans a few layers, and L spans several layers or requires new policy and persistence. The work column names data, routes, events, and UI. A dash means no new work in that layer. Existing rows list the scope to retain or to extend if the owner chooses an option.

## A. Chat

[`routes/web.php`](../routes/web.php) registers chat history, previous and next pages, last seen, viewers, send, edit, seen, delete, and attachment delivery. [`GroupController`](../app/Http/Controllers/GroupController.php), [`ChatService`](../app/Services/ChatService.php), [`MessagePresenter`](../app/Services/MessagePresenter.php), the [chat view](../resources/views/building/group.blade.php) and [chat module](../resources/js/building/chat.js) define what those actions do. [`routes/channels.php`](../routes/channels.php) authorizes active members of each private complex channel. The only live event classes and client bindings are [NewChatMessage](../app/Events/NewChatMessage.php), [EditChatMessage](../app/Events/EditChatMessage.php) and [DeleteChatMessage](../app/Events/DeleteChatMessage.php). Proposed events below are possible additions, not current behavior. A private complex channel reaches every authorized subscriber in that complex, so recipient-specific payloads need a narrower channel or an authenticated read.
